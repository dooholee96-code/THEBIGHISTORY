# 빅 히스토리 연표 (Big History Timeline)

왕조·국가사와 주제사를 **한 장의 거대한 그림판에서 나란히 비교**하는 역사 연표입니다.
아기 토끼 **시로**(shirolee studio)가 시대를 깡충 건너는 테마입니다. 기본은 연한 종이(라이트), 설정에서 밤하늘(다크)이나 시스템 따라가기를 고를 수 있습니다.
서버도 데이터베이스도 없는 정적 웹앱이라 인터넷 없이도 동작하고,
PWA(홈 화면에 추가)나 Capacitor(iOS/Android)로 그대로 확장할 수 있습니다.

- **탐험 — 역사 전체가 한 장의 거대한 그림** — 세로는 시간(위가 옛날), 가로는 카테고리마다 한 열.
  상하좌우 어디로든 끌고 던지고(트랙패드·휠은 스크롤로 이동), 핀치·⌘/Ctrl+스크롤로 1만 년 단위에서 1년 단위까지 줌합니다.
  두 손가락을 함께 위로 밀면 **스타워즈 오프닝처럼 판이 뒤로 눕습니다**(과거가 저 멀리, 지금이 코앞).
  그림판은 **Three.js(WebGL2)** 로 GPU 에서 그리고, WebGL2 가 없는 기기에서는 Canvas 2D 로 대신 그립니다.
- **시대의 색** — 선사·고대·중세·근세·근대·현대. 움직이면 하늘이 그 시대의 색으로 서서히 바뀌고,
  그림판 뒤 무대에 장면별 **디오라마**(`art/*.svg`, 토끼들이 그 시대 안에서 논다 · 명화 오마주 포함)가 교차 페이드로 깔립니다.
- **상세 팝업은 짧게** — 사건을 누르면 **연도 · 사건 · 한 문장 설명 · 출처** 만 나옵니다.
- **시간 계기판** — 아래 알약에 지금 연도와 시대. 누르면 시대 띠(Scale of the Universe 2 의 막대를 본뜸)와
  같은 해 나라별 왕조를 보여 주는 **지금 이때** 가 펼쳐집니다.
- **다섯 개의 탭** — 연표 · 갈림길(대체역사) · 카테고리 · 검색(검색어 없이 열면 전체 목록, 시대순) · 설정

현재 데이터: **17개 카테고리 / 458개 항목** (모두 `status: draft` — 검토 전 초안입니다)

> ⚠️ **내용 신뢰도**: 458개 항목은 **전부 검토 전 초안**이고, 공인 자료로 연도를 확인해 출처를 단 것은 132개입니다(한국사 51·중국사 16·일본사 23·경제·건축·동양 칸 42).
> [4장 내용의 출처와 신뢰도](#4-내용의-출처와-신뢰도) 를 꼭 읽어 주세요.

## 1. 실행하기

### 가장 간단한 방법 — 파일로 바로 열기

`index.html` 을 브라우저로 열면 끝입니다. (`data/bundle.js` 를 대신 읽습니다. 아래 참고)

### 로컬 서버로 열기 (권장)

```bash
npm run serve          # npx serve -l 5173 .  → http://localhost:5173
# 또는 Node 없이
python3 -m http.server 5173
```

> **왜 두 가지인가요?**
> 브라우저는 `file://` 로 연 페이지가 `fetch()` 로 옆의 JSON 파일을 읽는 것을 막습니다.
> 그래서 JSON 원본을 그대로 담은 사본 `data/bundle.js` 를 함께 두고, `file://` 일 때는
> 자동으로 그쪽을 읽습니다. **JSON 을 고쳤다면 `npm run build` 를 한 번 실행**해서
> 사본을 갱신해 주세요. (로컬 서버로만 쓸 거라면 없어도 됩니다.)

### 데이터 검증 / 배포 준비

```bash
npm run validate       # 스키마 + 교차 검사 (오류가 있으면 종료 코드 1)
npm run fix            # era_note 같은 자동 채움 가능한 항목을 채운 뒤 재검증
npm run build          # validate + 버전 스탬프 + data/bundle.js 재생성
```

**코드나 데이터를 고쳤으면 배포 전에 반드시 `npm run build` 를 돌리세요.**
`scripts/stamp.js` 가 css/js 참조에 `?v=<해시>` 를 붙이고 `sw.js` 의 캐시 이름을
같은 해시로 맞춥니다. 이게 없으면 브라우저·서비스워커가 예전 파일을 계속 써서
**배포해도 화면이 그대로인** 문제가 생깁니다. (해시는 소스 내용에서 자동 계산)

의존성 설치(`npm install`)는 필요 없습니다. 검증기는 Node 기본 기능만 씁니다.

## 3. 데이터 다루기

### 3-1. 항목 하나 추가/수정/삭제

해당 파일(`data/korea-dynasty.json` 등)의 `entries` 배열만 고치면 됩니다.

```json
{
  "id": "korea-gojoseon",
  "category": "왕조사",
  "subcategory": "한국",
  "title": "고조선",
  "region": "동아시아",
  "start_year": -2333,
  "end_year": -108,
  "era_note": "기원전 2333년 ~ 기원전 108년",
  "description": "단군왕검 건국 전승에서 비롯된 한반도 최초의 국가로, 기원전 108년 한 무제의 침공으로 멸망했다.",
  "tags": ["고대", "국가형성"],
  "sources": ["국사편찬위원회 한국사 개설"],
  "status": "draft"
}
```

| 필드 | 규칙 |
|---|---|
| `id` | 전체 데이터에서 유일. 소문자·숫자·하이픈. 관례: `<데이터셋id>-<식별자>` |
| `category` / `subcategory` | 매니페스트에 등록한 값과 **정확히** 같아야 함 (검증됨) |
| `start_year` / `end_year` | **기원전은 음수** (기원전 2333년 → `-2333`). 연도 0은 쓰지 않음 |
| | 단일 사건은 `start_year` 와 `end_year` 를 같게 → 연표에 점(point)으로 표시 |
| `era_note` | 비워두면 `npm run fix` 가 `"기원전 2333년 ~ 기원전 108년"` 형식으로 채움 |
| `description` | **한 문장짜리 간략 해설, 100자 이내**(두 문장 이상이거나 100자를 넘으면 검증 경고). 상세 팝업과 검색 결과에 그대로 나온다 |
| `kind` | 항목 종류. `polity`(나라·왕조·제국·정권) · `era`(시대 구분: 헤이안 시대, 춘추시대, 일제강점기, 통일신라처럼 한 나라 안의 시기) · `trend`(흐름: 르네상스, 냉전) · `event`(사건: 전쟁, 혁명). **왕조·국가사 항목에는 꼭 적는다**(빠지면 검증 경고) — 왕조 칸은 `polity`·`era` 만 그리고, 계기판 '지금 이때'는 `polity` 를 나라마다 긴 것부터 2개까지 보여 주며, 그 해에 `polity` 가 없을 때만 `era` 하나로 대신한다(점선 칩) |
| `parent` | (선택) 상위 왕조·나라의 항목 id(같은 파일 안). 탐험 화면에서 상위 칸 안에 그린다 — 예: 무신정권 → `korea-goryeo`, 제1공화국 → `korea-rok`. 기간이 상위 밖으로 나가면 검증 경고 |
| `area` | (선택) 본토와 따로 오래 이어진 주변 지역 이름(탐라·류큐·에조 등). 국가사 열 오른쪽 가장자리 줄에 그린다 |
| `start_md` | (선택) 시작일의 월·일 `"MM-DD"`. **확인된 날짜만** 적는다(지금 화면에는 쓰지 않고 데이터로만 남긴다) |
| `art` | (선택) 이 항목에 넣을 삽화의 의도(작업 메모, 화면에는 나오지 않음) |
| `dating_note` | (선택) 연대의 근거·한계. 문헌 전승 연대, 추정치, 학설이 갈리는 연대면 여기에 밝힌다(검토용 기록. 팝업은 연도·사건·설명·출처만 보여 준다) |
| `sources` | **직접 확인한 자료만** 적는다(URL 권장). 팝업 맨 아래 `출처 · …` 로 나오고, 비어 있으면 '아직 확인 전(검토 전 초안)' |
| `status` | `draft`(검토 전) 또는 `reviewed`(검토 완료) |

수정 후:

```bash
npm run build     # 검증 + bundle.js 갱신
```

> **Claude Code 에게 부탁할 때**
> "조선 왕조 추가해줘, 1392~1897" 처럼 한 문장이면 됩니다.
> 해당 JSON 편집 → (필요하면) 매니페스트 갱신 → `npm run build` 까지 한 번에 처리됩니다.
> 별도 관리자 화면은 없습니다. 변경 이력은 git 로그가 검토 로그 역할을 합니다.

### 3-2. 새 국가 추가하기 (예: 베트남사)

**① 파일 만들기** — `data/vietnam-dynasty.json`

```json
{
  "$schema": "../schema/entries.schema.json",
  "dataset": "vietnam",
  "entries": [
    {
      "id": "vietnam-ly",
      "category": "왕조사",
      "subcategory": "베트남",
      "title": "리 왕조",
      "region": "동남아시아",
      "start_year": 1009,
      "end_year": 1225,
      "description": "탕롱(하노이)을 수도로 삼아 베트남의 독립 왕조 체제를 다졌다.",
      "tags": ["중세", "왕조"],
      "sources": ["위키백과 베트남사 개괄"],
      "status": "draft"
    }
  ]
}
```

**② 매니페스트에 한 줄 등록** — `data/index.json` 의 `datasets` 배열에 추가

```json
{
  "id": "vietnam",
  "file": "vietnam-dynasty.json",
  "track": "nation",
  "category": "왕조사",
  "subcategory": "베트남",
  "label": "베트남사",
  "color": "#c0392b",
  "region": "동남아시아",
  "order": 33
}
```

끝입니다. **화면 코드는 한 줄도 건드리지 않습니다.** 레인·필터 칩·색상이 자동으로 생깁니다.

### 3-3. 새 카테고리(주제) 추가하기 (예: 의학사)

국가 추가와 똑같습니다. `category` 를 `"의학사"`, `track` 을 `"theme"` 로 두면 주제사 그룹에 붙습니다.
아예 새로운 트랙(예: `"경제사 묶음"`)을 만들고 싶다면 `data/index.json` 의 `tracks` 에
`{"id": "economy", "label": "경제·사회사", "order": 3}` 을 추가하고 데이터셋의 `track` 에 그 id를 쓰면 됩니다.

### 동양·서양 나누기

음악·미술·철학·문학은 동양과 서양을 따로 둡니다(`*-west.json` / `*-east.json`).
나누는 기준은 항목의 `region` — **동아시아·남아시아는 동양, 그 밖(유럽·지중해·서아시아·아메리카·세계)은 서양**입니다.
이슬람 철학처럼 서아시아에서 그리스 전통을 이은 것은 서양 쪽 흐름에 둡니다. 종교·과학·기술은 지역을 넘나드는 흐름이라 나누지 않았습니다.

### 3-4. 매니페스트 필드 요약

| 필드 | 설명 |
|---|---|
| `tracks[]` | 화면 위쪽 필터의 큰 묶음 (`nation`=왕조·국가사, `theme`=주제사) |
| `datasets[]` | 데이터 파일 목록. `id·file·track·category·subcategory·label·color` 필수 |
| `datasets[].order` | 레인 정렬 순서 (작을수록 위) |
| `datasets[].hidden_by_default` | `true` 면 처음에 꺼진 상태로 시작 |
| `datasets[].periods` | (국가사) **시대 묶음** `{label, start_year, end_year, note}` — 열 왼쪽 띠에 세로로 적힌다. 시작 순, 겹치지 않게. 경계 연도는 공인 자료(교과서·국사편찬위원회 등)의 시대 구분을 따르고, 어디서 끊었는지는 `note` 에 |
| `eras[]` | **시대 구간**. 화면의 시대 섹션·계기판 구간·배경 팔레트가 전부 여기서 만들어진다 |
| `eras[].start_year` / `end_year` | 그 시대에 들어갈 사건의 `start_year` 범위 (끝값은 포함하지 않음) |
| `eras[].day` / `night` | 배경 그라데이션 두 색 (위→아래). 낮/야경 각각 |
| `eras[].day_blob` / `night_blob` | 배경에 떠다니는 블롭 두 색 |
| `eras[].art` | 그 시대에 넣을 삽화의 의도. 넓은 화면의 여백에 자리표시자로 표시된다 |

### 3-5. 시대 장면(디오라마) 나누기

시대 하나에 그림 한 장이면 긴 시대(고대 등)에서는 같은 그림이 계속 이어져 밋밋합니다.
그래서 시대 안을 **장면**으로 나눕니다. `data/index.json` 의 `eras[].scenes` 에 시작 연도 순으로 적으면 됩니다.

```json
"scenes": [
  { "id": "ancient-river", "label": "강가의 첫 문명", "start_year": -3500, "diorama": "art/ancient.svg" },
  { "id": "ancient-dice",  "label": "주사위 놀이",   "start_year": -550,  "diorama": "art/homage-dice.svg",

```

- 장면은 그 시작 연도부터 다음 장면 직전까지 이어집니다.
  그림은 그림판 뒤 화면 크기의 **무대**에 깔려 있어, 초점선의 해가 그 구간에 있는 동안 보이고
  경계에서는 앞뒤 그림이 교차 페이드로 바뀝니다. 구간을 지나는 동안 그림이 아주 조금 위로 흘러 깊이감을 줍니다.
- 그림판에는 장면이 시작되는 해에 점선과 `· 장면 이름` 이 표시됩니다.
- 폰에서는 그림을 화면 폭의 2.6배로 키워 왼쪽 무대와 오른쪽 무대 사이를 천천히 오갑니다.
- 계기판을 펼치면 `고대` 아래에 `주사위 놀이`처럼 장면 이름이 나옵니다.
- 그림은 1600×900(viewBox `0 -200 1600 900`)으로, 표·카드가 덮는 **가운데는 비우고 좌우에** 무대를 둡니다.
  `art/_shiro.svg` 의 시로와, 장면 SVG 안의 `#bun`(털빛을 `fill` 로 바꾸는 친구 토끼)을 씁니다.
- 줄이 너무 적은 장면은 금방 지나가니, 장면마다 7줄 이상이 되도록 나누는 것을 권합니다.
- 검증기가 그림 파일 존재, 시작 연도 순서·범위, 장면 id 중복을 검사합니다.

**명화 오마주** — 장면에 `after`(원작 표기)를 적으면 설정 탭 '명화 오마주'에 자동으로 출처가 나옵니다.
**저작권이 끝난(퍼블릭 도메인) 작품만** 씁니다. 기준은 작가 사망 후 70년이 지났고(한국·EU),
미국에서는 1931년 이전 발표작인 것입니다. 구도만 빌려 새로 그리고, 원작의 사진·스캔 이미지는 쓰지 않습니다
(미술관 사진에는 별도 권리가 있을 수 있음). 지금 쓰는 10점은 모두 이 기준을 만족합니다.

### 3-6. 갈림길(대체역사) 시나리오 쓰기

가상의 역사는 **`data/alt/` 에만** 둡니다. 실제 연표 매니페스트(`data/index.json`)와 섞이지 않으므로,
가상 내용이 실제 연표에 나타나는 일은 없습니다.

1. `data/alt/<id>.json` 을 만들고 `data/alt/index.json` 의 `scenarios` 에 `{ "id", "file" }` 한 줄을 더한다.
2. `npm run validate` → `npm run build`.

시나리오 한 편은 **노드(node)를 id 로 이어 붙인 갈래 이야기**입니다. 예시는 `data/alt/sample.json`(내용은 자리표시).

| 필드 | 뜻 |
|---|---|
| `anchor` | 갈라지는 지점. `entry` = 실제 연표 항목 id, `year`, `note` = 그때 실제로 일어난 일 |
| `compare` | '실제 역사' 칸에 나란히 보여 줄 카테고리 id (예: `["korea","china"]`) |
| `start` | 첫 노드 id |
| `status` | `sample`(틀 확인용) · `draft`(쓰는 중) · `ready`(완성) — 앞의 둘은 화면에 배지로 표시 |
| 노드 `kind: "event"` | 가상 사건. `next` 로 다음 노드 |
| 노드 `kind: "choice"` | 갈림길. `options` 2개 이상, 각 선택지는 `to`(정해진 결과) **또는** `outcomes`(확률로 갈림: `[{ "chance": 0.7, "to": "…", "label": "…" }]`, 합 1) |
| 노드 `kind: "ending"` | 결말. `reality` 에 '실제로는 ~' 을 적는다 |
| 노드 `real` | (선택) 견줘 볼 실제 항목 id — 범위 밖이어도 '실제 역사' 칸에 나온다 |

검증기가 잡아 주는 것: 없는 노드로 이어짐, 고리(끝나지 않는 이야기), 시작에서 닿지 않는 노드,
확률 합이 1 이 아님, 실제 연표에 없는 항목 id, 거꾸로 가는 연도(경고).

### 3-7. 공개 데이터와 대조하기 (scripts/sources)

항목을 공개 데이터와 견주어 연도를 확인하는 도구입니다. **데이터 파일은 바꾸지 않고 리포트만** 만듭니다 —
무엇을 고치고 들일지는 사람이 리포트를 보고 정합니다.

```bash
npm run sources:match          # = node scripts/match-wikidata.js  (받은 응답은 .cache/sources 에 남아 다음엔 빠름)
node scripts/match-wikidata.js --fresh   # 모두 새로 받기
```

결과: `data/review/wikidata-report.md`(사람용 표) · `data/review/wikidata-match.json`(항목별 후보·연도·판정)

| 출처 | 라이선스 | 쓰는 곳 |
|---|---|---|
| [Wikidata](https://www.wikidata.org) | CC0 | 한국어 이름으로 항목을 찾고 시작·끝 연도(설립·해체, 시작·끝, 출생·사망, 발표, 발견·발명, 초연)를 견줌 |
| [Cliopatria](https://github.com/Seshat-Global-History-Databank/cliopatria) (Seshat) | CC BY 4.0 | 국가사 항목에 '지도에 그려진 기간'을 참고로 붙임 — 건국·멸망 연도가 아니고, Wikidata 연결이 틀린 곳도 있어(조선 → 고조선) 보조로만 |

- 판정: **일치**(시작·끝 모두 허용 오차 안) · **부분 일치** · **어긋남**(이름이 같은데 연도가 다름 — 먼저 볼 것) · **날짜 없음** · **못 찾음**
- 허용 오차는 Wikidata 날짜의 정밀도(1년·10년·100년…)와 시대(기원전 1000년 이전 ±25년, 서기 500년 이전 ±5년) 중 큰 쪽
- Wikidata 조회 결과의 날짜는 국제표준이라 0년이 있습니다(−0036 = 기원전 37년). 우리 방식(0년 없음)으로 바꿔 비교합니다
- **Wikidata 는 누구나 고칠 수 있어 맞다는 보증이 아닙니다.** 어긋남은 국사편찬위원회·민족문화대백과 같은 공인 자료로 어느 쪽이 맞는지 확인하고, 확인한 자료를 `sources` 에 적습니다
- 요청 제한: Wikimedia 는 많은 요청을 보내는 IP 를 잠시 막습니다(429). 공용 IP 에서 막히면 스크립트가 몇 분 뒤에 다시 하라고 알리고 멈춥니다.
  받은 것은 캐시에 남으니 다시 실행하면 이어집니다. 내 컴퓨터나 GitHub Actions(`.github/workflows/sources.yml`, Actions 탭 → sources → Run workflow)에서 돌려도 됩니다

## 4. 내용의 출처와 신뢰도

**이 연표의 내용은 아직 검증되지 않았습니다.** 지금 상태를 있는 그대로 적습니다.

- 458개 항목이 **전부 `status: draft`** 입니다.
- **한국사 51개 항목 전부**는 연도를 한국학중앙연구원 『한국민족문화대백과사전』 **원문 페이지**와 대조해 `sources` 에
  `[항목명],『한국민족문화대백과사전』 + 주소` 를 달았습니다(확인표: `data/review/korea-check.md`, 추가 9개: `data/review/korea-new.md`).
  대조는 Claude 가 했으므로 사람이 다시 확인하기 전까지는 `draft` 로 둡니다. 팝업에는 `출처 · <항목 링크> (검토 전 초안)` 로 나옵니다.
- 나머지 358개는 아직 출처가 없습니다. 368개에는 Wikidata 번호를 붙여 공개 데이터와 연도를 견줄 수 있게 했습니다.
- 항목의 연도와 설명은 **개설 수준의 통설을 요약한 초안**입니다. 특정 자료를 펼쳐 놓고
  대조한 것이 아니므로, 세부 연도나 표현에 오류가 있을 수 있습니다.
- 초기 버전에는 각 항목에 `"Encyclopaedia Britannica 개괄"` 같은 출처 문자열이 붙어 있었지만,
  이는 **항목별로 확인한 인용이 아니라 파일 단위로 일괄 부여된 라벨**이었습니다.
  검증된 것처럼 오해될 수 있어 **모두 비웠습니다.** 지금은 팝업에 '출처 미확인' 으로 정직하게 표시됩니다.
- 연대가 **문헌 전승·추정·학설 대립**인 항목과 기간을 어디서 끊었는지가 갈리는 항목 64개에는 `dating_note` 를 달아 근거와 한계를 밝혔습니다.
  (고조선·삼국 건국 연대, 하상주단대공정 연대, 석가모니·예수 생몰, 메소포타미아 연대기,
  선사 시대 구간 등)

### 검토해서 신뢰도를 올리는 방법

1. 항목의 연도·내용을 **직접 자료로 확인**합니다.
2. `sources` 에 확인한 자료를 적습니다. 되짚을 수 있는 형태가 좋습니다.
   ```json
   "sources": [
     "https://ko.wikipedia.org/wiki/고조선",
     "국사편찬위원회, 『한국사』 4권, 12쪽"
   ]
   ```
3. `status` 를 `reviewed` 로 바꿉니다.
4. `npm run validate` — **`reviewed` 인데 `sources` 가 비어 있으면 오류로 막습니다.**
   검증 결과 맨 끝에 `출처 표기: n/400` 로 진행 상황이 나옵니다.

git 커밋 이력이 그대로 검토 로그가 되므로, 누가 언제 무엇을 확인했는지 남습니다.

## 5. 화면 사용법

### 연표 탭 — 탐험

역사 전체가 **한 장의 거대한 그림**입니다 — 세로는 시간(위가 옛날),
가로는 카테고리마다 한 열(국가사 → 주제사). 그림은 화면보다 커서 **상하좌우 어디로든** 끌고 던질 수 있고,
줌하면 시간축과 열 너비가 함께 변합니다(멀리서는 모든 열이 한눈에 보이는 포스터, 다가가면 열이 넓어져 카드가 펼쳐짐)
(ChronoZoom 처럼 실제 시간 비율 — 선사 3만 년이 길고 문명사는 아래쪽에 모여 있는 것이 빅 히스토리의 실제 모습).

| 동작 | 방법 |
|---|---|
| 확대·축소 | 핀치(손가락·트랙패드 — 손가락을 그대로 따라감), `⌘`/`Ctrl`+휠(마우스 — 한 칸씩 부드럽게), `+` / `-`, 빈 곳 두 번 톡·더블클릭 = 다가가기. 모두 커서·손가락 자리 기준 |
| 이동 | 상하좌우 끌기 — 손가락·마우스를 1:1로 따라오고, 던지면 그 방향으로 미끄러짐. 끝(역사 처음·지금, 첫·마지막 열)을 넘기면 고무줄처럼 덜 따라오다 놓으면 튕겨 돌아온다(열이 화면에 다 들어와도 옆으로 밀린다). **트랙패드 두 손가락 스크롤·마우스 휠**(위아래 = 시간, 옆 = 열. 맥의 관성 스크롤 그대로), 윈도 마우스는 `Shift`+휠로 가로, `↑↓←→`, `PageUp/Down` — Figma·Miro·tldraw 같은 무한 캔버스 앱의 표준 조작 |
| 눕히기 | 스타워즈 오프닝처럼 그림판을 뒤로 눕힌다 — 과거가 저 멀리, 지금이 코앞. **두 손가락을 나란히 대고 함께 위로 밀면 눕고 아래로 당기면 선다**(벌리고 오므리면 줌), `Alt`(맥 `Option`)+휠, `Alt`+끌기, `T` 키(0° ↔ 40°). 최대 60°, 5° 아래로 놓으면 납작하게 돌아온다. 눕혀도 초점 고리의 해는 그대로이고, 끌기·톡·줌이 모두 손가락 밑의 점 기준으로 동작한다. `Ctrl`·`⌘`+휠은 줌(트랙패드 핀치도 브라우저가 `Ctrl`+휠로 보낸다. 사파리는 gesture 이벤트) |
| 열 | 화면 위에 열 이름이 붙어 있다. 열 이름을 톡 치면 그 열로 다가간다 |
| 연도 축 | 국가사 열과 주제사 열 **사이에 끼어** 그림과 함께 옆으로 움직인다(처음엔 화면 가운데). 화면 밖으로 나가려 하면 왼쪽·오른쪽 가장자리에 붙어 따라오고, 오른쪽에 붙으면 눈금이 그림 쪽을 보게 뒤집힌다. 국가사만·주제사만 켜면 맨 앞에 |
| 시대로 날아가기 | 시대 이름 톡, 계기판 `‹ ›`, `1`~`6`, 계기판 띠 — 멀면 잠깐 물러났다 다가가는 비행 |
| 시간 눈금 | 줌에 맞춰 1만 년 → 1천 년 → 100년 → 10년 → 1년 |
| 사건 | 자리가 넉넉하면 **카드**, 빠듯하면 **이름표**, 더 빠듯하면 **점**, 그래도 없으면 `+N` 묶음(톡 → 그쪽으로 다가감). 나라·왕조 > 시대 > 나머지 순으로 자리를 잡는다 |
| 왕조 칸 | 국가사 열은 왕조·시대를 **이름이 들어간 칸**으로 그립니다(왕조 표처럼). 같은 때의 나라는 열 폭을 나눠 나란히(혼자면 꽉 차게), 하위 시기(`parent`)는 상위 칸 안에, 주변 지역(`area`)은 오른쪽 가장자리 줄에. 이름은 보이는 부분 위쪽에 붙어 따라오고, 좁으면 세로로 씁니다. 초점선의 해에 걸린 칸이 진해집니다. 톡 → 상세 |
| 시대 묶음 | 국가사 열 왼쪽 띠(매니페스트 `periods` — 삼국 시대·송원 시대·중세 …). 톡 → 그 시대로 |

| 지금 어디? | 왼쪽 연도 축의 숨 쉬는 **고리**(초점선)에 걸린 해가 계기판 숫자가 된다 |
| 계기판 | 아래 알약 `‹ 기원전 653년 고대 ˄ ›`. 숫자를 누르면 **시대 띠**(톡 → 날아가기, 끌기 → 따라오기)와 **지금 이때**(초점선의 해에 나라마다 이어지던 나라·왕조, 나라마다 최대 2개 · 없으면 시대 이름 점선 칩 · 누르면 상세)가 펼쳐지고, 그림판을 다시 만지면 접힌다 |
| 상세 팝업 | 사건을 누르면 화면 가운데에 **연도(카테고리 색 점) · 사건 · 한 문장 설명 · 출처**. 닫기는 `Esc`, 바깥 영역, `✕`, 카드 머리를 아래로 끌어내리기 |
| 키보드 | `↑↓` 조금 · `PageUp/Down`·`Space` 한 화면 · `←→` 옆 열 · `+−` 줌 · `T` 눕히기 · `1`~`6` 시대 · `Home/End` · `/` 검색 |

**조작감을 바꾸고 싶다면** `js/zoom.js` 맨 위 상수를 고치면 됩니다 —
`FRICTION`(작을수록 멀리 미끄러짐), `RUBBER`(끝 너머로 따라오는 비율), `SPRING`(되돌아오는 빠르기), `TILT_MAX`·`TILT_ON`(눕히는 각도).
`prefers-reduced-motion` 을 켠 기기에서는 날아가기·눕히기 같은 연출 없이 바로 이동합니다.

**그리기** — 판(열·사건·눈금)은 `js/plane.js` 의 붓이 칠합니다. Three.js(WebGL2)가 되면 모든 도형을 인스턴스 한 번으로,
글자는 한 번 쓴 문자열을 글자판 텍스처(한 채널, 밉맵)에 두고 다시 써서 GPU 로 그리고, 눕히기는 원근 카메라를 기울입니다.
WebGL2 가 없으면 Canvas 2D 로 칠하고 눕히기는 CSS 3D 로 합니다(주소 뒤에 `?2d` 를 붙이면 이 모드를 확인할 수 있음).
열 이름·시대 이름은 판 위에 납작하게 붙은 덮개 캔버스에 그려 눕혀도 똑바로 읽힙니다.

화면 읽기 프로그램을 쓰거나 사건을 글로 차례대로 읽고 싶다면 **검색 탭**을 여세요 — 검색어가 없으면 전체 항목이 시대순으로 나옵니다.

### 퀴즈 탭 (데모)

카드게임 'Timeline' 처럼 **사건 카드를 한 장씩 받아 연표의 알맞은 자리에 끼워 넣습니다**(다섯 장).
- **오늘의 퀴즈** — 날짜로 정해지는 카드라 같은 날엔 모두 같은 문제. 결과(🟩🟥… n/5)를 나눌 수 있고, 그날 결과는 이 기기에 남습니다
- **연습** — 아무 카드나
- 카드는 **출처가 확인된 항목**에서만 나옵니다(시작 해가 서로 다른 것). 놓인 카드를 누르면 탐험 그림판의 그 자리로 가서 상세가 열립니다

### 갈림길 탭

실제 역사의 한 장면에서 다른 길을 골라 가는 **가상 역사**. 같은 시간축에 왼쪽(모바일은 위) 실제 역사, 오른쪽(모바일은 점선 카드)
가상 역사가 나란히 놓이고, 갈림길부터 점선 줄기가 갈라져 나온다.

- 선택지를 고르면 다음 가상 사건이 이어진다. '결과는 확률로 갈림' 선택지는 고른 뒤에 결과가 정해진다(70%·30% 등).
- 결말에서는 '실제로는 ~' 과 견주고, `한 단계 되돌리기`로 다른 길을 보거나 `처음부터` 다시.
- 진행 상황은 기기에 저장되어 다음에 `이어서 하기`.
- 실제 연표의 항목 팝업에 그 항목에서 갈라지는 시나리오가 있으면 `갈림길 · …` 버튼이 나온다.

### 카테고리 탭

내용 신뢰도 고지, 데이터·소프트웨어 라이선스, 개인정보 고지.

## 6. 배포

### 6-1. GitHub Pages (웹)

빌드 과정이 없으므로 저장소를 그대로 올리면 됩니다.

1. `npm run build` 로 `data/bundle.js` 를 최신화하고 커밋합니다.
2. GitHub 저장소 → **Settings → Pages → Source: Deploy from a branch**
3. 브랜치(예: `main`)와 폴더 `/ (root)` 를 선택하면 `https://<계정>.github.io/<저장소>/` 로 열립니다.

모든 경로가 상대 경로라서 하위 경로 배포에서도 그대로 동작합니다.

### 6-2. PWA (앱스토어 없이 "홈 화면에 추가")

`manifest.webmanifest` 와 `sw.js` 가 이미 들어 있습니다. **https 또는 localhost** 로 열면
서비스워커가 등록되어 오프라인에서도 동작하고, 모바일 브라우저에서 "홈 화면에 추가"를 하면
주소창 없는 앱처럼 실행됩니다.

서비스워커는 **네트워크 우선**으로 동작합니다. 온라인이면 항상 서버의 최신 파일을 쓰고,
네트워크가 없거나 느릴 때만(4초) 캐시 사본으로 대체합니다. 배포 때마다 `npm run build` 로
버전 스탬프가 바뀌므로 새 코드가 곧바로 반영됩니다.

> **예전 버전이 계속 보인다면** (캐시 우선이던 옛 서비스워커가 남아 있는 경우)
> 주소 뒤에 `?v=2` 를 붙여 한 번 열거나, 새로고침을 두 번 하세요.
> 그래도 그대로면 개발자도구 → Application → Service workers → **Unregister** 후 새로고침.
> 지금 어떤 빌드가 떠 있는지는 브라우저 콘솔의 `[app] 빅 히스토리 연표 <해시>` 줄로 확인합니다.

### 6-3. Capacitor (iOS / Android 앱스토어)

이 앱은 웹 표준만 쓰고 데이터도 파일 기반이라(브라우저 저장소에 의존하지 않음)
**코드 수정 없이** 네이티브로 감쌀 수 있습니다.

```bash
npm install @capacitor/core @capacitor/cli
npx cap init "빅 히스토리 연표" com.example.bighistory --web-dir=.
npm install @capacitor/ios @capacitor/android
npx cap add ios
npx cap add android
npx cap sync          # 웹 자산을 네이티브 프로젝트로 복사
npx cap open ios      # Xcode  (App Store 제출)
npx cap open android  # Android Studio (Play Store 제출)
```

- `webDir` 를 저장소 루트로 두면 `index.html`·`css/`·`js/`·`data/` 가 그대로 앱 번들에 들어갑니다.
  (`node_modules`, `ios`, `android`, `scripts` 는 `.gitignore`/`.capacitorignore` 로 제외)
- 네이티브 앱에서 글꼴을 외부에서 받지 않으려면 `index.html` 의 Google Fonts 링크를 지우거나,
  글꼴 파일을 앱 번들에 포함하고 `@font-face` 로 바꾸세요(SIL OFL 이라 재배포 가능).
- 네이티브 WebView 는 `capacitor://` 스킴이라 `fetch` 가 동작하므로 JSON 을 직접 읽습니다.
  `data/bundle.js` 는 그대로 두어도 무해합니다.
- 데이터가 바뀔 때마다 앱을 다시 심사받고 싶지 않다면, 나중에 `data/` 만 원격에서
  내려받아 갱신하는 식으로 `js/data.js` 한 파일만 고치면 됩니다.

### 6-4. Three.js 다시 묶기 (vendor/three.min.js)

파일로 바로 열기(`file://`)에서도 돌도록 ES 모듈 대신 전역 `THREE` 하나로 묶어 둡니다.
`js/plane.js` 가 쓰는 것만 골라 묶어서 전체(약 1.2MB)보다 작습니다(약 470KB, gzip 120KB).
새 클래스를 쓰게 되면 아래 `entry.js` 에 이름을 더하고 다시 묶으세요.

```bash
mkdir /tmp/three-build && cd /tmp/three-build && npm init -y && npm i three@0.170.0 esbuild@0.24.0
cat > entry.js <<'JS'
export {
  WebGLRenderer, Scene, Camera, Mesh,
  InstancedBufferGeometry, InstancedBufferAttribute, BufferAttribute,
  ShaderMaterial, DataTexture, Vector2,
  RGBAFormat, RedFormat, UnsignedByteType, LinearMipmapLinearFilter, LinearFilter,
  DynamicDrawUsage, CustomBlending, OneFactor, OneMinusSrcAlphaFactor,
  REVISION
} from 'three';
JS
npx esbuild entry.js --bundle --minify --format=iife --global-name=THREE --target=es2018 \
  --legal-comments=none --outfile=<저장소>/vendor/three.min.js
```

묶은 뒤 파일 맨 위에 출처 한 줄 주석을 다시 달고, `npm run build` 로 스탬프를 갱신하세요.
